# What is version control and why Git?

Have you ever worked on a document and saved files like this?

- `essay_final.doc`
- `essay_final_v2.doc`
- `essay_final_REALLY_final.doc`
- `essay_final_FIXED.doc`

This is a form of version control, but it is messy. As developers, we edit hundreds of files. We need a better system.

## Introducing Git

Git is a "Version Control System" (VCS). It tracks every single change you make to your code.

Think of it like a **time machine** for your project.

### Why we use Git

1.  **Undo Mistakes**: deleted a critical file? Broke your code? You can travel back in time to when it worked.
2.  **History**: You can see exactly _who_ changed a line of code, _when_ they did it, and _why_.
3.  **Collaboration**: Multiple people can work on the same file at the same time without overwriting each other's work.
4.  **Backup**: Your entire project history is saved.

## "Save Points" in Video Games

Imagine you are playing a difficult video game. Before a boss fight, you create a **Save Point**. If you lose, you reload the save point.

In Git:

- A **Commit** is like a Save Point.
- You make changes, and when you are happy, you "commit" them.
- If you mess up later, you can revert to that commit.
