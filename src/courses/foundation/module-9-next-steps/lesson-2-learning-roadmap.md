# Building a Learning Roadmap

Learning to code is a marathon, not a sprint. If you try to learn "everything," you will burn out. You need a structured plan.

## The Strategy: Reverse Engineering

Instead of starting with "What should I learn today?", start with "Where do I want to be in 6 months?"

**Example Goal:** "I want to be hired as a Junior Frontend Developer."

Now, work backwards:

1.  **To get hired:** I need a portfolio with 3 good projects.
2.  **To build projects:** I need to know React and connecting to APIs.
3.  **To learn React:** I need to master modern JavaScript.
4.  **To master JavaScript:** I need to practice algorithms and DOM manipulation.

## Setting SMART Goals

- **S**pecific: "Learn JavaScript" is too vague. "Build a To-Do list in JavaScript" is specific.
- **M**easurable: You know when you are done.
- **A**chievable: Don't say "Clone Facebook in 1 week."
- **R**elevant: don't learn C++ if you want to be a web developer.
- **T**ime-bound: "By next Friday."

## Frequency over Intensity

It is better to code for **30 minutes every day** than for 8 hours on Saturday.

- Your brain needs sleep to solidify new concepts.
- Large gaps make you forget what you learned.

## The "Tutorial Hell" Trap

Many beginners get stuck watching video after video without ever building anything.
**Rule of Thumb:** For every hour of video you watch, spend 2 hours building something with what you learned, _without_ the video playing.
